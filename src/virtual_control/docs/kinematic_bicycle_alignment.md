## 중심점 예측

위치·지도·상하위 경로 좌표는 차체 중심으로 유지한다. 공유 odometry를
뒷차축으로 옮기지 않는다. `v`는 중심점 수평 합성속도, `L=2.8`, `lr=1.4`다.

```
beta = atan(lr/L * tan(delta))
center_velocity = v * [cos(yaw+beta), sin(yaw+beta)]
yaw_rate = v/L * cos(beta) * tan(delta)
```

하위 MPC는 작은 조향각 근사를 사용한다. 고정 접선 좌표에서
`e_y_dot = v * (e_psi + lr/L * delta)`, `e_psi_dot = v/L * delta`이며
조향 1차 응답을 포함해 한 구간 동안의 횡이동과 회전을 적분한다.
경로 접선 방향과 비교하는 출력은 차체 yaw 자체가 아닌
`e_psi + lr/L * delta` (진행 방향 오차)다. QP 실패 시 오차 피드백에도
`atan(lr/L*tan(estimated_delta))`를 반영한다.

곡률은 진단용이다. 상태 방정식·fallback에 곡률 입력을 복원하지 않았다.
시작 방향 연속성 제한과 soft ratio 규칙도 변경하지 않았다.

새 두 파라미터의 기본값은 0이다. 기준점 거리 0에서는 기존 뒷차축 식을,
명령 환산값 0에서는 기존 최대 조향각 기반 환산을 유지한다.

`/debug/lower_mpc_trace` 기존 0–29번 필드는 유지하고 30번에 기준점 거리,
31번에 명령 환산값을 추가했다. 7번은 종전대로 차체 yaw 오차다.
MATLAB의 기존 30열 CSV 소비자는 추가 필드를 무시하며 rosbag에는 모두 저장된다.

## 검증 범위와 남은 문제

별도 ROS domain의 하위 MPC 테스트에서 연속 운동식 RK4 적분과 예측 행렬을
대조한다. 비선형 중심점 자전거 주행에는 3/6 m/s, 좌우 곡선,
시정수 0.03/0.08 s, 추가 지연 20 ms, yaw 측정 잡음 약 1도를 사용한다.
실제 MAVLink 출력과 차량 구동 없이 정규화 명령 경로까지 검사한다.

실행 결과: `virtual_control` 빌드 성공. 하위 MPC 19개, 조향 응답 3개 및
heading guard 테스트 묶음이 모두 통과했다. 비선형 주행 8조건에서 횡오차
RMS는 0.0584–0.0664 m, 시작 오차 0.5 m를 포함한 최대 오차는
0.499–0.508 m, 10초 이후 최대 오차는 0.0364–0.0594 m였다.
이는 모의시험 결과이며 실제 주행 성능 수치가 아니다.

기존 하위 PID 60828의 목표 정지·출력 0 상태를 확인한 뒤 새 PID 76735로
교체했다. ROS domain 1의 실제 trace에서 지연 0, 시정수 0.05, 거리 1.4,
환산 0.35와 정지 mode 4/조향 0/스로틀 0을 확인했다. 자동 arm이나 주행
시작은 하지 않았다. 상위 플래너와 PX4 브리지는 계속 기존 프로세스로 실행한다.

직전 로그에서 EKF yaw와 SIH truth의 차이는 최대 약 14.1도였다.
브리지 로그의 초기 heading check 통과는 주행 중 추정 오차가 없다는 뜻이 아니다.
현재 수정은 이 EKF 오차를 해결하지 않는다. EKF 입력을 truth로 바꾸거나
heading guard를 해제하지 않았다. 재주행 bag으로 실제 추종을 확인해야 한다.

또한 목표 도달 때 가상 brake가 MAVLink의 적극 제동으로 전달되지 않는
기존 문제가 남아 있다. 이 변경에 역방향 스로틀을 제동으로 추가하지 않았다.
