# 실제 진행량 기반 경로 연결과 곡률 입력 제거

2026-09-23 23:20 주행 분석 후 사용자 요청에 따라 적용한 변경이다.
과거 `sih_sway_tuning.md`의 곡률 입력 기반 시험 결과는 이 모델의 검증 결과가 아니다.

## 하위 제어

하위 오차 상태 예측의 `-v*dt*kappa_ref` 항을 두 모델(즉시 조향/지연 조향)
모두에서 제거했다. 예측은 최근접점의 고정 접선 좌표계에서 현재 횡오차·방향오차와 조향 입력으로 진행한다.
미래 경로의 위치와 방향은 그 좌표계로 표현해 비용함수의 추종 목표로 사용한다.
곡률을 미분/적분해 상태를 강제로 움직이는 항은 없다.
QP 실패 시에도 곡률 feed-forward 없이 `-0.35*ey - epsi`로 명령을 만들고
기존 조향각·변화율 제한을 적용한다.

경로의 방향은 현재 방향오차 계산에 계속 사용한다. 곡률 배열과 trace[28]은
기존 진단 형식 유지를 위해 남아 있지만 상태 예측·목적함수·fallback 명령에
영향을 주지 않는다. 측정 속도로 샘플링한 미래 점과 방향은 추종 목표이며, 곡률만 진단용이다.
조향 응답 delay=0.30 s, tau=1.00 s 및 N=30은 유지한다.

## 상위 이전 경로 재사용

기존에는 old p1을 무조건 버리고 old p1을 원점으로 전체 prefix를 평행이동했다.
이제 현재 차량 위치를 이전 경로의 선분에 투영해 경로상 진행량 s0를 구하고,
`s0 + k * planning_speed * upper_dt`에서 이전 경로를 다시 샘플링한다.

r0는 현재 차량 위치다. 미래 점은 이전 경로의 world 위치를 보존하므로 횡방향
오차를 지우기 위해 곡선 전체를 차량 쪽으로 이동시키지 않는다. 현재 yaw로
body frame으로 변환하며, 이전 경로 끝을 넘으면 마지막 유효 선분 방향으로
연장한다. 마지막 두 preview 점의 기존 terminal 구성은 유지한다.
중복점은 제거하며 비정상 좌표/길이 입력은 거부한다.

## 시작 방향 연결 기능 제거 (2026-09-24)

00:15 주행에서 추가한 시작 방향 제약이 경로 생성을 막는 것을 확인했고,
사용자 요청에 따라 이 기능을 제거했다. 첫 선분의 두 각도 제한, 추가 최소
전진 거리 제한, yaw rate 기반 허용각 계산 및 설정 파라미터를 모두 삭제했다.
대신 방향 벌점이나 다른 연속성 기능을 추가하지 않았다.

기존 도로 경계와 차량 입력 제약은 유지한다. 실제 위치 기반 이전 경로
재샘플링과 하위 곡률 상태 입력 제거/미래 위치·방향 추종도 유지한다.
상위 N=5, dt=0.9 s, 목표 속도 6 m/s는 유지한다.

### 비용함수의 기하 추종 목표

각 미래 시점의 목표 횡위치는 최근접점 접선의 법선에 미래 경로점의 상대 위치를
투영한 값이다. 목표 방향은 미래 경로 접선과 현재 기준 접선의 방향 차이다.
MPC는 예측 차량 상태와 이 목표의 차이를 최소화한다. 따라서 곡률 배열을
임의로 바꿔도 상태 행렬·예측·명령은 변하지 않지만, 미래 경로 위치·방향을
바꾸면 명령은 달라진다. 곡률 항만 제거해 미래 경로 정보를 모두 잃는 단순
오차 조절 방식은 6 m/s 곡선 시험에서 기존 1 m 최대 오차 기준을 넘겨 채택하지 않았다.

## 시작 방향 기능 제거 전 검증 기록

- 빌드·설치 성공. 관련 CTest 5개 타깃 모두 통과: 상위 지오메트리,
  구간 처리, 경로 생성/시작 방향 제약, 하위 MPC, 조향 응답 모델.
- 곡률 배열만 100 /m로 바꿔도 예측 상태·행렬·조향 및 fallback 결과가 동일하다.
- 곡률을 모두 0으로 두어도 미래 경로 위치·방향이 달라지면 추종 명령이 달라진다.
- 실제 진행량 투영, 횡방향 오차 보존, 회전 좌표계, 중복점·끝점 연장 검사 통과.
- 첫 방향 제한과 도로 제한을 함께 만족하는 해만 허용하고, 서로 충돌하는
  합성 조건에서 경로가 거부되는지 검사했다.
- 독립 비선형 차량 곡선 시험(조향 지연·시간상수·이득·헤딩 오차 변동 포함):

| 3 m/s | 0.85 s | 0.166 m | 0.527 m |
| 3 m/s | 1.30 s | 0.192 m | 0.534 m |

이 시험은 고정된 S자 기준 경로를 쓰므로 Isaac의 지도·상위 재계획을 포함한
폐루프 검증을 대체하지 않는다. 운영 상·하위 제어기는 새 실행 파일로 재시작해야 한다.

### 시작 방향 기능 제거 전 녹화 입력 재생

별도 domain 177, localhost, MAVLink 및 하드웨어 출력 비활성 상태에서
23:20:55 녹화의 경로·차량 상태·그리드만 원래 속도로 재생했다.
상위 130회 중 124회 성공, 6회 도로/시작방향 제약을 동시에 만족하지 못해 거부했다.
모든 시도의 N은 5이며, 발행된 첫 선분 방향은 계산한 허용 범위 안이었다
(수치상 최대 위반 7.8e-16 rad). 하위 641회 유효 QP는 모두 조향 제한을 지켰다.
초기 입력 대기 이후 stale path 중립 출력 10회가 발생했다. 연속 세 번씩의
상위 거부가 기존 1.5초 경로 만료 정책을 작동시켰고, 성공 경로 최대 간격은 약 2초다.

이 재생은 변경 전 차량 궤적을 강제로 입력하는 시험이므로 새 제어 명령으로
차량이 어떻게 움직일지는 보여주지 않는다. 특히 기존 이탈 구간에서 새 경로가
거부되는 제한이 남아 있다. 실제 폐루프 주행 안정화가 확인됐다고 해석하면 안 된다.
자료는 `drive_debug_20260923_232054_light/analysis/requested_changes_replay*.json/txt`
및 같은 디렉터리의 `requested_changes_*tests.log`에 있다.
