# Soft ratio 적용 및 완화 확인 — 2026-09-24

## 결론

저장된 실제 주행 데이터에서 중앙 수축과 경계 여유 방식이 모두 적용되며,
완화된 구간도 솔버가 선택하는 것을 확인했다. 다만 현재 실행 파일은
중간 구간 누락으로 N이 줄어들 때, 뒤쪽 관측을 기준 길이 B 계산에서 제외한다.
이는 문서와 기존 통합 시험이 요구하는 전체 프리뷰 기준과 다르다.
운영 제어 로직은 이번 확인에서 수정하지 않았다.

## 현재 계산의 의미

`preview_interval_soft_ratio=0.7`은 원래 폭의 70%를 남기는 설정이 아니다.
양 끝에서 각각 원래 길이 L의 30%를 빼므로 ON일 때 중앙 40%가 남는다.

- 신뢰할 수 있는 관측 중 기준점이 포함된 구간들의 최소 길이를 B 후보로 선택.
- 기존 B가 없거나 후보 <= 1.5*기존 B이면 즉시 갱신. 더 큰 후보는 보류.
- 관측 길이 L <= 1.5*B: ON, 처리 길이 0.4*L.
- 그 외: OFF, 처리 길이 L - 2*min(2m, 0.45*L).
- nominal fallback은 별도 9m 기준. 현재 폭 4.5m라 ON → 1.8m.

예를 들어 원래 폭 10m라면 ON 4m, OFF 6m다. OFF도 원래 도로 전체를
허용하는 것은 아니다. 짧은 구간에서는 OFF가 ON보다 더 좁을 수 있다.
특히 L < 6.667m에서 이 이름을 항상 '완화'로 해석하면 안 된다.
아래 실제 기록의 OFF 구간은 모두 ON보다 넓었다.

이 기능은 길이에 따른 두 처리 방식의 전환이다. 솔버 실패에 따라 ratio를
0.7→0.8→0.9로 올리거나 slack 변수를 써서 도로 제약을 푸는 기능은 없다.
처리된 경계는 MIQP와 direct QP 양쪽에 실제 제약으로 들어간다.

## 발견한 통합 경로 문제

`src/virtual_control/src/tracking_control.cpp:1502`에서
`observations.resize(output.N_pred + 1)`을 먼저 실행한 뒤 B를 계산한다.
중간 k=3에 구간이 없으면 N=2가 되고 k=4,5의 관측은 B 후보에서 빠진다.
진단 상세 메시지에는 뒤쪽 관측이 남기 때문에 '관측은 있는데 B에 반영되지
않는' 상태가 발생한다.

실행 파일로 재현한 기존 통합 시험 결과:
- 초기 B=4.8m.
- 중간 k=3 막힘 → N=2.
- k=5에서 기준점을 포함하는 3.9m 구간을 관측.
- 기대: B=3.9m, 판정 기준 5.85m.
- 실제: 앞쪽 7.9m만 후보로 판단, 기존 B=4.8m 유지, 기준 7.2m.

이 시험에서는 앞쪽 7.9m가 두 기준 모두에서 OFF이므로 해당 장면만으로
실제 경로가 좁아졌다고 주장하지 않는다. 다만 B 갱신 누락이 검증됐고,
5.85~7.2m 사이 구간에서는 ON/OFF 결정 자체가 달라질 수 있다.
수정 후보는 B용 전체 관측을 유지하고 솔버에 전달할 구간만 잘라내는 것이다.
현재 정책 의도와 일치하는지 확인해 반영할 사항이다.
