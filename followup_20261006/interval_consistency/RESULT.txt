2026-10-06 후속 2차 — 근거리 허용 구간 급변의 원인 분리 및 대응 검증

결론
근거리 축소 규칙 변경 3안은 이번 기록 재생에서 분기 회귀가 있어 운영에 반영하지 않았다.
조향 흔들림을 해결했다고 주장하지 않는다. 제어기 소스/설정/바이너리는 그대로 유지했다.
실제 반영한 변경은 경량 기록기의 BEV 진단 토픽 추가 1줄뿐이다.
첨부 BEV 생성기에는 원래 지도 출력 결정을 유지하는 진단 전용 사본을 준비했다.
생성기 패키지가 이 PC에 없으므로 다른 PC에 설치/실행하지 않았다.

1. 실제 기록의 원인을 나누면
scenario3 S1=01:41:43, S2=01:43:03, x190..245/y140..180 구간의 실제 trace 22주기.
현재 원단면을 고정하고 B만 직전 값으로 되돌린 반사실 계산으로 인과 항목을 분리했다.

확정:
- k1에서 0.5m 이상 횡이동이 강제된 주기: S1 5/12, S2 4/10.
- 그 9주기 중 B 갱신만 되돌려 차이가 생기는 것은 2주기다.
  S1 01:42:02: 원폭10.3m, inset2.00 ->3.09m, 최소 강제이동0 ->0.703m.
  S2 01:43:19: 원폭10.6m, inset2.00 ->3.18m, 최소 강제이동0.045 ->1.225m.
  같은 S2 주기의 k2도 B 갱신으로 최소이동0 ->1.041m.
- 가장 큰 S1 01:41:55~56 변화는 B를 되돌려도 그대로다.
  55초: 원단면까지0.167m, 처리 후1.683m; 56초: 원단면까지0.985m, 처리 후2.425m.
  이때 두 좁은 후보는 전후 B 모두에서 동일한 상대 축소를 받는다.
- 즉 B의 ON/OFF 불연속, 원단면 자체의 분리/변화, 기존 상대 축소의 증폭을 구분해야 한다.
  '근거리 후보 변화가 모두 B의 순간 변경 때문'이라는 가설은 이 기록에서 성립하지 않는다.

단면 그림: recorded_sections.png (가장 가까운 수신 BEV를 trace 자세로 배치한 시각화).
이 그림은 카메라 캡처 시각 정합을 증명하지 않는다.
수치: attribution.json/txt. 스크립트: attribute_changes.py.

2. 별도 사본에서 시험한 변경(하위 모델/비용/속도/분기 묶음은 고정)
0 baseline: 현재 운영 동작.
1 continuous_min: 관측된 k1~k2에 두 기존 inset 법칙의 작은 값 적용.
  min(0.3*원폭, min(2.0,0.45*원폭)). B 전환 불연속을 제거하는 실험.
2 fixed_margin: 같은 k1~k2를 기존 OFF 방식 min(2.0,0.45*원폭)으로 처리.
3 raw diagnostic: k1~k2의 inset만0. 원단면과 축소의 기여 분리용이며 차량 여유를 제거하므로 적용 후보가 아님.
4 delay_near_tightening: B 갱신으로 축소가 더 강해질 때 직전 계획이 있는 k1~k2만
  한 주기 동안 직전 B의 덜 강한 축소를 유지. 현재 원단면 경계와 원거리의 새 B는 즉시 반영.
명목 fallback 후보는 모두 기존 처리 유지. 비주행 셀 사이를 합치거나 새 주행 영역을 생성하지 않음.
1과2도 차량 footprint 안전을 새로 보증하는 설계는 아니다. 현재 상위 코드에는 폭/자세별 footprint 제약이 없다.

기록 BEV 재생: 네 기록, 각 5조건, 114주기/조건.
각 후보의 직전 계획은 이어가지만 차량 자세/BEV는 실제 기록 고정(폐루프 실주행 예측이 아님).
S1/S2 근거리 p95 창은 이전 실험과 같은, 첫 재생 위치부터 기록 궤적상35..110m.

원폭 진단은 흔들림 지표를 줄여도 마지막 분기를 해결하지 못했다. 폭 확대의 채택 근거가 되지 않는다.
미세한 초기 변경도 이전 계획 -> 다음 단면 -> 미래 분기 후보를 바꾸며 누적된다.
이 기록만으로 대안의 실제 차량 주행 실패를 확정하지는 않지만 운영 채택 근거는 부족하다.

- 곡선/분기폭: 각각2/2 목표 도달, 실패0.

- Y자: 각각12/12 정분기/목표 도달, 실패0.

- 대조군은 기존 결과와 폐루프56/56, 재생114/114 동일(atol1e-10).
합성 회귀를 모두 통과해도 실제 SC3 입력에서 나타난 회귀를 무시하지 않았다.

3. 지도 정합 진단(원인 확정 아님)
S1/S2/SC1 격자 stamp는 모두0. 같은 세계 위치의0.5초 간격 관측을 비교했다.
고정된 회전/직선 표본 집합으로 수신시각 대비 가정 지연0..0.5초를 조사했다.
근거리 회전 구간에서도 이전 free가 현재 blocked로 바뀌는 비율이 약9~10% 존재한다.
0.15~0.2초 가정으로 일부 일치도가 좋아지지만 근거리 개선은 작고 최적값도 구간별로 다르다.
따라서 '실제 지연이0.2초'라고 식별한 것이 아니며 제어기 시각에 보정값을 넣지 않았다.
투영/시각/분할/기준점 오류를 이 기록만으로 분리할 수 없다. map_consistency.json/txt 참조.

4. 사용자가 추가 제공한 rgb_to_occupancy.cpp 검토
첨부는 참고 소스이며 현재 다른 PC의 실행 바이너리/파라미터와 동일하다고 확인된 것은 아니다.
원본 바이트/해시를 bev_source/에 보존했다.

소스상 확정:
- gray <= road_gray_max AND NOT(gray >= white_line_gray_min)으로 주행 픽셀 결정.
  기본85/180에서는 흰 선이 비주행이 된다. 색상 기반이며 실제 장애물 의미를 구분하지 않는다.
- keep_largest_component=true(기본값)이면 morphology 후 최대 연결 영역 하나만 남긴다.
  매 프레임 독립적인 면적 비교이며 이전 영역과의 공간 대응은 없다.
- RGB 구독 KeepLast(10), 콜백 안에서 homography/warp/분할/형태연산/연결 영역/축소 수행.
  과부하 시 영상이 대기할 수 있는 구조이나, 실제 대기시간은 이번 bag으로 측정 불가.
- occupancy_grid_zero_stamp=true(기본값)는 이미지 시각을 삭제한다. false면 원본 이미지 시각을 전달한다.
- use_latest_tf=true(기본값)는 최신 camera<-Vehicle 변환을 사용한다.
  카메라가 차량에 강체 고정이면 상대변환이 일정할 수 있으므로 이것만으로 주행 중 오정합 원인을 단정하지 않음.
- ground_z 고정 평면 가정. 실제 피치/롤/캘리브레이션/왜곡 영향은 미검증.
- 실행 설정은 분명 일부 다르다: 첨부 기본 격자64/범위22.5m, 실제 기록128/40m.
  keep_largest/밝기문턱/TF 설정까지 기본값이라고 가정하지 않았다.

합성 영상 반례(실제 주행 원인 확정 아님):
40x40m, 해상도0.02m, 폭10m 회색 도로, 폭0.2m 흰 중앙선.
첨부 코드와 같은 영상 연산에서 중앙선 위치 -4cm ->+4cm만 변경:
  최대 영역만 유지: 남는 주행 영역 중심 +2.52m ->-2.54m, 128x128 격자3968셀 변경.
  모든 영역 유지: 2개 단면 유지, 이 샘플의128격자는0셀 변경.
이는 최대 면적 선택이 작은 입력 변화에 불연속일 수 있다는 재현이다.
해당 기록의 검은 영역이 흰 차선이었다거나 최대 영역 전환이 실주행 원인이라고 확정한 것은 아니다.

검증 한계:
첨부의 두 C++ 함수를 그대로 추출해 컴파일했으나 이 PC의 OpenCV 헤더4.8/공유라이브러리4.5 혼재 환경에서
실행이 SIGSEGV로 실패했다. 패키지를 설치/변경하지 않았고 동일 연산을 Python OpenCV4.12로 실행했다.
결과는 동등 연산 합성 시험으로 표기했다. 실제 C++ 생성기 실행 검증으로 세지 않는다.
bev_source/segmentation_fixture_python.json, native_attempt.json, source_fixture.py 참조.

5. 완료한 대응과 적용 상태
- 생성기의 분할/좌표/기존 파라미터는 바꾸지 않고 가벼운 진단 추가본 준비:
  bev_source/rgb_to_occupancy.diagnostics.cpp 및 diagnostics.patch.
  RGB 시각, 콜백 시각, 격자 publish 이후 시각, 계산시간, 실제 TF 시각,
  연결 영역 개수/면적 상위2개/총면적, 관련 실행 파라미터를 /debug/bev_source_timing에 발행.
  기존 연결 영역 stats 결과를 사용하며 영역 선택/지도 픽셀 결정식은 유지.
- 전체 진단 소스 C++ 구문 검사 통과. 해당 패키지 전체 빌드/실행은 이 PC에서 불가하여 미검증.
  std_msgs 의존성 반영이 필요할 수 있다. 다른 PC에는 적용하지 않았다.
- record_drive_debug.sh에 새 진단 토픽 추가. shell 구문 검사 통과. 기록이나 주행은 시작하지 않았다.
- baseline/ 11파일 백업과 before/applied 해시 보존. restore.py는 해시가 다르면 덮어쓰기 거부.
  python3 followup_20261006/interval_consistency/restore.py --restore 는 기록기1줄만 복원한다.
  제어기 소스/설정/바이너리를 바꾸거나 실행 중 프로세스를 정지하지 않는다.
