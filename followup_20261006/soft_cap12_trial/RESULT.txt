2026-10-06 soft 적용 폭 12 m 상한: 독립 재확인
결론: 오프라인 사본에만 구현·빌드. 분기 선택 회귀가 재현되어 운영 적용 보류.
운영 소스·헤더·YAML 변경, 운영 빌드/설치, 노드 재시작, 차량 명령 전송 없음.

1. 시험한 변경 (한 요소만)
관측 단면의 soft 문턱 = min(1.5 * B, 12 m).
상한 OFF = 기존 1.5 * B. B 갱신 규칙 자체는 수정하지 않음.
상한 초과 시 기존 경계 여유 2 m를 적용. nominal fallback의 9 m 문턱은 독립 유지.
실험 제어 변수는 사본에만 추가했으며 운영 파라미터로 설치하지 않음.
trial.patch가 운영 소스 대비 전체 변경을 보여 준다.

2. 기존 자료 확인과 정정
followup_20261006/j2_soft/RESULT.txt에 이미 동일 유형 시험의 상반된 효과가 기록되어 있었다.
직전 추천 시 이 보고서를 놓쳤다. 이번에는 요약만 인용하지 않고 현재 운영 소스에서
새 사본을 만들어 다시 컴파일하고, 기록된 planner pose와 각 bag의 설정으로 재확인했다.
이전 실험과 달리 fallback 문턱은 명시적으로 별도 유지한다.

3. 입력 및 비교 설계
bag 6개: 050536, 050627, 014143, 014303, 045314, 044738.
총 246개 시점 x 설정 2개 x 상한 OFF/12 m x 재생 방식 2개 = 1968회 상위 계획 계산.
설정 1: 각 bag의 config_snapshot.yaml.
설정 2: 이번 작업 시작 시 YAML의 사본(config_current.yaml).
최신 두 주행 당시: upper_r_dpsi=3, rate=2 Hz, wp=15/20, lower_rd=180.
현재 사본: upper_r_dpsi=2, rate=2 Hz, wp=15/20, lower_rd=150.
이 설정 변화는 이번 작업이 만든 것이 아니며 변경하지 않았다.
상위 단독 재생이므로 lower_rd는 계산에 참여하지 않는다.
주기 시각은 bag 기록 그대로 사용하므로, '현재 설정'도 기록된 시각의 상위 입력 재생이며
실제 2 Hz로 차량을 다시 주행시킨 결과가 아니다.

재생 방식:
- 0 (carried): 첫 주기의 B와 참조는 기록으로 초기화하고, 이후 이전 계획과 B를 매 주기 전달.
  차량 자세와 지도는 모든 안에 동일한 기록값을 제공하므로 차량 폐루프 시험은 아니다.
- 1 (fixed): 매 주기 참조, B_before, waypoint pair를 기록값으로 고정하고 같은 단면 입력에서
  soft 상한의 순간 효과만 비교. B와 참조 누적을 함께 차단하므로 둘의 개별 영향은 분리하지 않는다.

상위 이벤트의 x/y/yaw_rad를 그대로 사용. 일반 quaternion 변환 없음.
BEV는 계산 시작 전 가장 최근 수신 기록으로 연결했다. ROS 내부 수신 순서와 bag 기록 순서 차이는
완전히 제거할 수 없다. 기록 참조/B 고정 + 당시 설정 + 상한 OFF의 최신 두 bag은 유효 계획
122개 중 120개가 최대 점 오차 1 mm 이내로 재현됐다. 나머지 두 시점의 최대 점 오차는
050536에서 0.3700 m, 050627에서 0.1495 m다. 유효/실패는 최신 두 bag 전체 124시점에서 일치.
carried baseline도 최신 두 bag의 주요 분기 선택과 실패 횟수(0/2)를 재현한다.

실행: ROS_DOMAIN_ID=177, ROS_LOCALHOST_ONLY=1, ROS_LOG_DIR=실험 폴더.
타이머 취소, executor spin 없음, planner 직접 계산만 수행. 하위/직렬/MAVLink 출력 없음.
네트워크 제한으로 DDS 초기화 경고가 출력됐으나 수치 계산 결과는 정상 저장되고 프로세스 exit=0.
최초 시도는 ROS install 환경 누락으로 사용자 정의 메시지 라이브러리 로드에 실패했다.
install/setup.bash를 읽은 후 정상 완료했으며 권한 확장은 사용하지 않았다.

4. 핵심 결과 (계획/B를 전달하는 재생, 주행 당시 설정)
050536: 당시 북쪽 오분기 기록.
- 기존: 05:05:59.344~05:06:00.344에 북쪽 계획.
- 12 m: 같은 세 시점에는 동쪽 계획. 그러나 기록된 차량은 북쪽으로 계속 이동하므로,
  이후 계획 실패 1회와 북쪽 복귀가 발생. 실주행 정분기 성공으로 집계할 수 없다.

050627: 당시 동쪽 정분기 기록.
- 기존: 05:06:51.906에 동쪽 계획, 끝점 (139.34, 2.52).
- 12 m: 같은 시점 북쪽 계획, 끝점 (128.00, 12.75).
- 다음 세 시점에서도 북쪽 계획 유지. 오분기 회귀 보류 조건에 해당한다.
- 전체 재생 계획 실패는 2 -> 16회. 차량 자세는 실제 동쪽 주행으로 고정된 상태에서
  수정 계획은 북쪽으로 향하므로 이 수치를 실제 주행 실패 횟수나 정지 시간으로 해석하지 않는다.
- 분기 전후 진행 118~150 m 구간의 첫 계획 구간 방향 보정 절댓값 p95: 10.67 -> 26.48 deg.
  이는 상위 계획과 입력 참조의 방향 차이이며 조향각 또는 실제 차체 진동 측정값이 아니다.

014143: 전체 실패 1 -> 1. 계획 변화 없음.
014303: 전체 실패 0 -> 0. 근거리 방향 보정 p95 13.22 -> 11.66 deg.
045314: 전체 실패 0 -> 0.
044738: 전체 실패 0 -> 0. 실패가 없다는 것만으로 정분기를 의미하지 않는다.
SC3의 모든 갈래를 자동 분류해 성공률을 계산한 것은 아니며, 최신 정분기 기록의 회귀로
운영 적용 판단은 이미 탈락한다.

현재 설정(r_dpsi=2)으로 같은 입력을 재생한 경우:
050627은 상한 유무 모두 05:06:51.906부터 북쪽 계획이고 전체 실패 각 16회.
050536의 동쪽 계획 유지 시점도 두 안이 동일하다. 현재 설정에서도 상한의 일관된 개선은
확인되지 않았다. 이것은 현재 설정의 실제 주행 결과를 뜻하지 않는다.

5. 확인된 메커니즘과 미확정 부분
확정: 같은 기록 참조/B로 05:06:51.906 한 주기를 계산하면 상한 OFF/12 모두 동쪽이다.
그러나 이전 수정 계획과 B를 전달하면 12 m 안은 북쪽을 선택한다.
따라서 이 재생의 회귀는 그 시점의 soft 해제만으로 설명되지 않고, 앞선 계획 변경이
다음 주기의 참조·단면·B에 누적되는 과정과 함께 나타난다.

실제로 12 m 안은 05:06:50.906부터 B가 약 7 m로 내려간다(기존 14.7 -> 15.3 -> 17.8 m).
05:06:51.906의 k6 동쪽 후보 원폭/적용폭은 기존 2.7/1.08 m, 수정 2.0/0.80 m이다.
같은 BEV라도 참조에 따른 절단선이 달라지므로 raw 단면 자체도 달라졌다.
k5/k6 선택은 기존 0/0, 수정 1/1로 바뀐다. 이 비교에서 회전 비용 창은 양쪽 [3,4,5]로 같다.

강한 해석: 넓은 근거리 단면을 풀면 원하는 갈래로 미리 이동할 수 있는 자유도는 늘지만,
그것이 다음 주기의 좁은 갈래 접근성과 선택을 일관되게 개선하지는 않는다.
B 상승과 넓은 단면 축소가 관측된 사실 자체는 유지된다. 다만 'B 상한/soft 해제만으로
늦은 조향 및 오분기를 해결한다'는 해법은 이번 시험에서 지지되지 않았다.
미확정: 실제 차량 폐루프에서의 조향 RMS, 포화율, 최종 분기 성공률. 운영 적용을 막는
회귀가 이미 확인되어 추가 폐루프/실주행 시험과 운영 코드 설치는 진행하지 않았다.
