원하는 세트만 먼저 실행 (예: 기준 / 헤딩 비용 / 변화 한계 / 조향 비용, 총12회):

시나리오3에도 같은 비교를 적용:

모든 기본·추가 세트 이름 확인:
/home/imac/ros2_ws/run_parameter_sweep.sh --list

기존 반복 주행 실행기와 별도 제어기/기록기를 종료하고 실행한다.
이미 열려 있는 반복 실행 터미널이 잠금을 갖고 있으면 그 터미널도 종료한다.
모드 설정·ARM은 기존 수동 운용 방식이다.

Ctrl+C는 현재 세션에 중단을 요청하고 정지 확인을 기다린다.
입력·계산·준비 이상이나 정지 확인 실패가 있으면 다음 세트로 넘어가지 않는다.
주행 실패(off_route, 정체 등)는 정지 확인 후 예정 회차와 다음 세트를 계속한다.
중단한 계획은 같은 --resume 명령으로 이어서 실행한다.
완료한 세트는 건너뛰고, 미완료 세트는 새 기록 폴더에서3회 다시 실행한다.

sets.csv: 세트별 실제 설정
configs/: 실행에 사용할 고정 설정
plan.json: 예정 회차와 실행파일·경로 해시
progress.json: 완료 세트 / 현재 세트 / 중단 이유
summary.csv: 완료 세트의 회차별 결과를 모은 표 (실행 후 생성)
sessions/: 세트별 원본MCAP, 설정, 결과, 실행 로그

9세트:
1. 기준: 플래너5Hz / 제어10Hz / 하위예측3초
2. 플래너2Hz
3. 플래너10Hz
4. 제어20Hz / 하위예측3초(0.05초 ×60스텝)
5. 상위 도로 헤딩 비용0.3 (기준0.6)
6. 상위 도로 헤딩 비용1.2
7. 상위 헤딩 보정 비용6.0 (기준3.0)
8. 상위 조향 한계0.25rad로 헤딩 변화 한계 강화 (기준0.30rad)
9. 하위 조향 변화 비용300 (기준150)

현재 모델의 헤딩 변화 한계는 조향 한계·예측 간격·예측 속도로 정해진다.
8번은 독립적인 고정 헤딩각 제한을 새로 추가하는 대신, 기존 제약식을
조향 한계로 강화한다. 하위 차량의 물리 조향 한계는 그대로다.
추가 세트: 하위 헤딩 비용, 조향 변화속도 제한, 비용 조합, 짧은20Hz예측.

회차 전환의 최소 정지 확인1.0→0.5초, 지도 정렬 대기1.0→0.3초,
경로 준비 대기1.0→0.3초. 정지와 새 입력이 확인되어야 출발한다.
실제 차량이 멈추는 관성 이동 시간은 생략하지 않는다.
최근 시나리오1 기록은 준비·정지 포함 약63초/회였으므로 기본27회는
대략25~35분을 예상한다. 입력 복구/정지 상황에 따라 더 걸릴 수 있다.
