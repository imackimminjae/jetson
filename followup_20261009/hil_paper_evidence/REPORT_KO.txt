이 자료는 기존 HIL 기록의 검증·시각화 묶음이다. 논문 원고가 아니다.

기존 보고서의 p95·속도>1m/s·완화 포화 기준과 집계 정의가 달라 수치 차이는 개선 효과가 아니다.

모든 유효 표본에서 허용 오차 1e-5rad 내 만족했다.

S1 54/3928, S2 50/6214, S3 91/3295였다. 이를 '출력 변화율 위반 없음'으로 쓸 수 없다.
내역: S1 기준명령 변경 35/시간간격 영향 19,
      S2 기준명령 변경 33/시간간격 영향 15/중립·모드 전환 등 2,

개별 리셋의 근본 원인까지 확정한 분류는 아니다. output_rate_exceedances.csv에 전 건 수록.

5. 도로 제약·차량 안전의 증거 수준

계획 노드가 선택된 처리 구간의 측방 투영 범위 안에 있는지 사후 재검사했다.
1mm 허용 오차 기준 S1 4680노드, S2 4488노드, S3 3827노드에서 초과 0.
S3 보호 로직으로 제약을 제외한 tail 3노드는 분모에서 제외했다.
S3 검사 노드 중 3개는 관측 구간이 아닌 nominal fallback 구간이며 CSV source_mode로 구분된다.
원래 해의 수치 잔차 최대는 S1 0.636mm, S2 0.419mm, S3 수치 오차 수준.
이는 선택된 측방 slab의 노드 제약 검사이며, 노드가 단면 선분 위에 정확히 놓이는지의 검사가 아니다.
구간 사이 보간 궤적·차량 중심의 실제 도로 이탈·차량 외곽 충돌을 보증하지 않는다.

실제 차량 중심의 독립 도로 이탈: 평가 불가.
  기록은 EKF 유래 상태와 인식 격자이며, 독립적인 참 도로 경계/차량 truth가 동시 기록되지 않았다.
  모든 grid header timestamp가 0이라 원 영상 시점 및 정확한 차량/격자 동시성이 미확보다.
차량 외곽 도로 이탈/충돌: 평가 불가.
  폭·정확한 collision mesh 미확보. 전방만 관측하므로 현재 차량 뒤쪽은 격자 바깥이다.
최소 실제 경계 여유거리: 평가 불가.
  plan_interval_checks의 margin은 처리 구간에 대한 계획 노드 투영 여유이며 실제 차량 경계 여유가 아니다.
독립 도로 중심선 기준 오차: 평가 불가.
  waypoint polyline을 독립 도로 중심선으로 대신 사용하지 않았다.
오분기하였어도 도로 안에 있었는지는 별도 판정 항목이며, off_route와 동일시하지 않았다.

6. HIL 편향 조건

확인한 8개 drive_batches의 effective_config 모두 enable_waypoint_bias=false.
최신 세 배치 기록 파라미터·시작 로그와도 모순이 없다. yaw_bias_rad=0.17은 비활성 설정값이다.
기존 기록에서 위치/heading 편향을 인가한 것으로 식별·검증할 수 있는 HIL cohort는 미확보.
명목 SD 경로와 관측 도로의 어긋남은 관측할 수 있지만, 알려진 편향량을 통제한 실험은 아니다.
구현의 편향 변환식, 추가 계측·실험 조건은 BIAS_AND_MISSING_KO.txt와 missing_data.csv에 별도 정리.
오프라인 반사실 재계산 결과를 HIL 편향 주행 결과로 대체하지 않았다.

7. 자료 위치·재계산·되돌리기

tables/: 회차별 거리·시간·오차·조향·실패, 실행시간 분포, 구간 검사, 전체 배치 인벤토리.
signals/: 위치·하위 32필드 trace·상위 사건·단계별 시간·실제 하위 경로·B·로그의 CSV/JSONL gzip.
scenes/: 연속 장면의 작은 선택 격자, 원 기록 경로, 시각/출처, 합성 배경 투표 격자.
configs/: 주행별 실제 합성 실행 설정, 원 manifest, 세션 결과, 기록 파라미터, 현재 호스트 확인값.
sources/: 원본 목록 및 SHA256, 원본과 현재 실행 파일 비교, 코드 계측 정의, 신호 사전, 그림 출처.
원본 MCAP는 drive_batches의 원래 위치에 유지. 별도 raw_HIL_logs.tar에 8개 배치의
원본 bag·실행 설정·시작 로그·결과를 그대로 묶는다. 지도 디코딩 캐시를 만들지 않았다.

동일 workspace에서 재계산(운영 노드/토픽을 생성하지 않는 파일 읽기):
  cd /home/imac/ros2_ws
  source /opt/ros/humble/setup.bash
  source /home/imac/ros2_ws/install/setup.bash
  export ROS_DOMAIN_ID=177 ROS_LOCALHOST_ONLY=1 OPENBLAS_NUM_THREADS=1
  python3 followup_20261009/hil_paper_evidence/build_evidence.py

  python3 followup_20261009/hil_paper_evidence/supplement.py
  python3 followup_20261009/hil_paper_evidence/finalize.py

기존 분석 telemetry를 재사용하지만 원본 SHA256을 전부 확인했고,
원본 MCAP에서 모든 위치·하위 trace를 다시 읽어 정확히 대조했다.
추가 하위 경로, 파라미터, 격자 장면은 MCAP에서 직접 추출했다.
extraction_validation.json 및 최종 검증 파일에 표본 수와 파일 보존 결과를 남긴다.
현재 스크립트는 이 workspace의 기존 분석 경로를 사용하므로, 원시 로그만 다른 컴퓨터로
옮겨 실행하려면 ROOT/REVIEW 경로 또는 텔레메트리 입력을 맞춰야 한다.
운영 변경이 없어 운영 rollback은 필요 없다. 이 산출물이 불필요하면 새
followup_20261009/hil_paper_evidence 폴더와 옆의 전달용 archive만 제거하면 된다.
기존 미커밋 파일을 git reset/checkout으로 되돌리지 말 것.

8. 논문에서 설명 가능한 결과와 부족한 주장

설명 가능:
  이 HIL 구성에서 상위 계획과 하위 추종이 반복 실행되었으며, 명목 경로 조건의
  최신 S1/S2/S3 목표 접근은 각각 9/10, 0/10, 10/10이었다.
  기록된 분기 후보·선택 계획·실행 궤적을 연결해 정분기와 오분기 사례를 제시할 수 있다.
  현재 하위 참조 기준의 추종오차 및 계획 노드 구간 제약 검사 결과를 재계산할 수 있다.
  상위 실행시간 분포와 1회의 500ms 초과, 하위 solver의 부분 실행시간을 정량 제시할 수 있다.
  풀이 거부 때 경로 유지, 오래된 경로에서 중립, 입력 단절과 관성 이동을 사례로 설명할 수 있다.

아직 근거 부족:
  모든 시나리오에서 안정적 완주, 목표 정차 성공, 물리 차량/실측 센서 검증,
  실제 바퀴각 추종, 차량 외곽 전체 무충돌·도로 내 보장, 편향에 대한 출구 선택/도로 유지 내성,
  하위 전체 콜백 deadline 보장, end-to-end 지연 상한, WCET 또는 일반적인 성공률 보장.
  S3의 분기·목표 접근 성적이 가장 좋다는 사실을 모든 추종 지표가 가장 좋다는 주장으로 넓히지 않는다.
  오프라인 상태 재계산의 효과를 실제 폐루프 주행 성공 보장으로 표현하지 않는다.
